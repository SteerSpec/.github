# Contributing to SteerSpec

Thanks for your interest. SteerSpec is in early development and we welcome feedback, bug reports, and ideas.

## Where to contribute

- **Spec changes** → [strspc-spec](https://github.com/steerspec/strspc-spec)
- **Sync action** → [strspc-sync](https://github.com/steerspec/strspc-sync)
- **CLI** → [strspc-CLI](https://github.com/steerspec/strspc-CLI)
- **Rule format** → [strspc-rules](https://github.com/steerspec/strspc-rules)
- **PR auto-approve action** → [strspc-pr-review](https://github.com/steerspec/strspc-pr-review)
- **Manager** → [strspc-manager](https://github.com/steerspec/strspc-manager)

## How to contribute

1. Open an issue first to discuss the change you'd like to make.
2. Fork the relevant repo and create a branch from its default branch — that is `main` in most repos, but `develop` in some (check before you branch), and it is also where your pull request should land.
3. Make your changes, then open a pull request with a clear description.

Some repos add their own conventions on top of this — conventional commit messages, a pull request checklist, tests that must pass. Where a repo has a `CONTRIBUTING.md`, an issue form, or a pull request template of its own, follow that; it wins over this page.

## Code of conduct

Be direct, be constructive, be kind. The long version is the [Contributor Covenant](CODE_OF_CONDUCT.md), which applies across every SteerSpec repository.

## Security

Never report a vulnerability as a public issue — use the private channel described in the [security policy](SECURITY.md).
